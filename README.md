# kad_arbitr_api — API картотеки арбитражных дел (kad.arbitr.ru)

REST API на FastAPI для поиска дел и извлечения документов из картотеки
арбитражных дел [kad.arbitr.ru](https://kad.arbitr.ru). Идея и разбираемая
разметка результатов поиска основаны на скрипте
[yuglebov/kad_arbitr_ru](https://github.com/yuglebov/kad_arbitr_ru).

kad.arbitr.ru блокирует прямые HTTP-запросы к своим внутренним ручкам, поэтому
вместо `requests` используется headless-браузер (Playwright): страницы
загружаются как в обычном браузере, а данные достаются из готового HTML.

## Возможности

- `POST /search` — поиск дел по участнику, судье, суду, номеру дела и периоду
  регистрации;
- `GET /cases/{case_id}` — карточка дела: номер, суд, судья, стороны, список
  документов;
- `GET /cases/{case_id}/documents` — только список документов дела;
- `GET /documents/{case_id}/{document_index}` — скачивание конкретного
  документа (PDF), номер `document_index` берётся из поля `document_id`
  в списке документов (`{case_id}:{index}`).

## Установка и запуск

```bash
pip install -r requirements.txt
python -m playwright install --with-deps chromium
uvicorn kad_arbitr_api.app:app --host 0.0.0.0 --port 8000
```

Документация Swagger доступна на `http://localhost:8000/docs`.

### Запуск в Docker

```bash
docker build -f Dockerfile.kad_arbitr -t kad-arbitr-api .
docker run --rm -p 8000:8000 kad-arbitr-api
```

## Настройки (переменные окружения)

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `KAD_BASE_URL` | Базовый адрес kad.arbitr.ru | `https://kad.arbitr.ru` |
| `KAD_HEADLESS` | `0`, чтобы видеть окно браузера при отладке | `1` |
| `KAD_REQUEST_DELAY` | Пауза между операциями, сек (снижает риск капчи) | `1.5` |
| `KAD_NAV_TIMEOUT_MS` | Таймаут навигации/ожидания элементов, мс | `30000` |

## Ограничения

- Сайт может показать капчу при подозрении на автоматический трафик — API не
  пытается её решать (это не поддерживается и не входит в задачи проекта),
  а возвращает `503` с понятным сообщением: нужно снизить частоту запросов и
  повторить позже.
- Запросы обрабатываются последовательно (одна блокировка на браузер), чтобы
  не создавать нагрузку, похожую на бота — это ограничивает пропускную
  способность API.
- CSS-селекторы в `kad_arbitr_api/parser.py` привязаны к текущей вёрстке
  kad.arbitr.ru и могут потребовать обновления при изменении сайта.
- Используйте API только для законного получения общедоступных сведений о
  делах — картотека является официальным публичным ресурсом Федеральных
  арбитражных судов РФ.

# Перенос данных с Google Drive на Яндекс.Диск

Консольная программа на Python, которая рекурсивно копирует файлы и папки
из Google Drive на Яндекс.Диск, сохраняя структуру каталогов.

Возможности:

- рекурсивный обход всех папок и подпапок;
- Google-документы (Docs/Sheets/Slides/Drawings) автоматически
  экспортируются в форматы `.docx` / `.xlsx` / `.pptx` / `.png`, так как
  их нельзя скачать в исходном виде;
- обычные файлы скачиваются и заливаются как есть, потоково, без
  загрузки всего файла в память;
- при сбое или повторном запуске уже перенесённые файлы не переносятся
  повторно (прогресс хранится в `migration_state.json`).

## Установка

```bash
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка доступа к Google Drive

1. Зайдите в [Google Cloud Console](https://console.cloud.google.com/),
   создайте проект (или выберите существующий).
2. В разделе "APIs & Services" включите **Google Drive API**.
3. В разделе "OAuth consent screen" настройте экран согласия (тип
   "External", добавьте свой email в тестовые пользователи).
4. В разделе "Credentials" создайте **OAuth client ID** типа
   "Desktop app" и скачайте JSON — сохраните его как `credentials.json`
   в корне проекта.
5. При первом запуске программы откроется браузер для авторизации —
   после подтверждения токен сохранится в `token.json` и повторно
   вводить логин/пароль не потребуется.

## Настройка доступа к Яндекс.Диску

1. Зайдите на https://oauth.yandex.ru/client/new и создайте приложение.
2. В разделе доступа отметьте **Яндекс.Диск REST API**: чтение и запись
   (`cloud_api:disk.read`, `cloud_api:disk.write`, либо весь диск —
   `cloud_api:disk.app_folder` если нужна только папка приложения).
3. Получите OAuth-токен по ссылке вида
   `https://oauth.yandex.ru/authorize?response_type=token&client_id=<ID приложения>`.
4. Скопируйте `.env.example` в `.env` и впишите токен:

   ```
   YANDEX_TOKEN=ваш_токен
   ```

## Запуск

```bash
python main.py
```

По умолчанию переносится весь Google Drive в папку `/GoogleDriveBackup`
на Яндекс.Диске. Доступные параметры:

```bash
python main.py \
  --source-folder-id root \        # ID папки Google Drive (root = весь диск)
  --dest-path /GoogleDriveBackup \ # путь на Яндекс.Диске
  --credentials credentials.json \
  --token token.json \
  --state-file migration_state.json
```

ID конкретной папки Google Drive можно взять из её URL:
`https://drive.google.com/drive/folders/<этот_id>`.

Если перенос прервался (сеть, лимиты API и т.п.) — просто запустите
`python main.py` ещё раз с теми же параметрами, программа продолжит с
того места, где остановилась.

## Запуск в Docker (чтобы потом легко всё снести)

Удобно, если не хочется ставить Python и зависимости на VDS напрямую —
после переноса просто удаляешь образ и контейнер, и от программы не
остаётся следов в системе.

1. Создай на хосте папку для файлов, которые должны пережить контейнер
   (`credentials.json`, `token.json` с авторизацией, `.env` и файл
   прогресса `migration_state.json`):

   ```bash
   mkdir data
   cp credentials.json data/
   cp .env.example data/.env   # впиши туда YANDEX_TOKEN
   ```

2. Собери образ:

   ```bash
   docker build -t gdrive2yadisk .
   ```

3. Запусти контейнер. Порт 8080 нужен для одноразовой OAuth-авторизации
   Google (ссылку для входа нужно будет открыть в браузере на своей
   машине — в консоли она распечатается):

   ```bash
   docker run --rm -it \
     -p 8080:8080 \
     -v "$(pwd)/data:/app/data" \
     --env-file data/.env \
     gdrive2yadisk \
     --credentials /app/data/credentials.json \
     --token /app/data/token.json \
     --state-file /app/data/migration_state.json
   ```

   Если VDS без графического окружения — просто скопируй ссылку,
   которую программа выведет в консоль, и открой её в браузере на своём
   компьютере (не на сервере). После подтверждения доступа токен
   сохранится в `data/token.json`, и повторно логиниться не придётся.

4. Если перенос прервался, просто выполни ту же команду `docker run`
   ещё раз — прогресс лежит в `data/migration_state.json` на хосте и
   переживёт удаление контейнера.

### Фоновый запуск (чтобы можно было закрыть терминал/SSH)

Пока идёт одноразовая авторизация Google (шаг 3 выше), контейнер должен
быть в интерактивном режиме (`-it`) — но после того как `data/token.json`
уже создан, повторный вход в браузере не требуется, и контейнер можно
запускать в фоне флагом `-d`, никак не завися от открытого терминала:

```bash
docker run -d \
  --name gdrive-migration \
  -v "$(pwd)/data:/app/data" \
  --env-file data/.env \
  gdrive2yadisk \
  --credentials /app/data/credentials.json \
  --token /app/data/token.json \
  --state-file /app/data/migration_state.json
```

Смотреть прогресс можно в любой момент, даже переподключившись позже:

```bash
docker logs -f gdrive-migration
```

`Ctrl+C` в `docker logs -f` только отключает просмотр логов, сам перенос
при этом продолжает идти в контейнере. Когда перенос закончится,
контейнер остановится сам (в логах будет "Перенос завершён.") — удали
его командой `docker rm gdrive-migration`.

5. Когда всё перенесено — сносим всё, что связано с программой:

   ```bash
   docker rmi gdrive2yadisk   # контейнер и так удалился благодаря --rm
   rm -rf data/               # удаляет token.json, credentials.json и прогресс
   ```

   На VDS после этого не останется ни образа, ни контейнера, ни
   сохранённых токенов.

## Перенос Google Фото (через Google Takeout)

Google с марта 2025 года закрыл программный доступ к чтению всей
библиотеки Google Фото для обычных (непрошедших верификацию) приложений
— API-ключ вроде того, что мы получили для Google Drive, для Фото уже
не работает. Единственный надёжный способ забрать **все** фото и видео
— выгрузить их через Google Takeout, а дальше эта же программа сама
разложит их по Яндекс.Диску.

1. На своём компьютере зайди на https://takeout.google.com, нажми
   **Deselect all**, отметь только **Google Photos**, выбери формат
   `.zip` и максимальный размер архива (например, 50 ГБ — так частей
   будет меньше). Google подготовит архив и пришлёт письмо со ссылками
   на скачивание, когда всё будет готово (может занять от часов до
   суток при большой библиотеке).
2. Скачай все части архива (`takeout-*.zip`) себе на компьютер, затем
   перенеси их на сервер, например через `scp` (в папку `data/takeout`,
   её нужно создать):

   ```bash
   # на сервере
   mkdir -p ~/transfer/data/takeout

   # на своём компьютере, из папки со скачанными архивами
   scp takeout-*.zip root@АДРЕС_ТВОЕГО_VDS:~/transfer/data/takeout/
   ```

3. Запусти перенос (образ `gdrive2yadisk` тот же, что и для Drive —
   просто переопредели entrypoint на `takeout_main.py`). Google-авторизация
   тут не нужна, поэтому сразу можно в фоне:

   ```bash
   docker run -d \
     --name gphotos-migration \
     --entrypoint python \
     -v "$(pwd)/data:/app/data" \
     --env-file data/.env \
     gdrive2yadisk \
     takeout_main.py \
     --source-dir /app/data/takeout \
     --dest-path /GooglePhotosBackup \
     --state-file /app/data/takeout_state.json
   ```

4. Смотреть прогресс:

   ```bash
   docker logs -f gphotos-migration
   ```

   Сначала программа распакует архивы (это может занять время и потребует
   на диске места примерно вдвое больше суммарного размера архивов —
   сами `.zip` и распакованные файлы лежат одновременно), затем начнёт
   заливать фото и видео на Яндекс.Диск в папку `/GooglePhotosBackup`,
   сохраняя структуру альбомов. При сбое просто перезапусти ту же
   команду `docker run` — уже загруженные файлы не задублируются
   (прогресс в `data/takeout_state.json`).

5. После успешного переноса можно удалить архивы и распакованные файлы,
   чтобы освободить место на VDS:

   ```bash
   rm -rf ~/transfer/data/takeout
   ```

## Ограничения

- Файлы нестандартных типов Google (Формы, Сайты, Jamboard и т.п.) не
  поддерживают экспорт в обычный файл и будут пропущены.
- Общие диски (Shared Drives) поддерживаются, но для них может
  потребоваться передавать ID общего диска как `--source-folder-id`.
- Учитываются лимиты API Google Drive и Яндекс.Диска — при очень
  больших объёмах данных перенос может занять продолжительное время.
- Google Фото переносятся только через Google Takeout (см. раздел выше)
  — прямого программного доступа ко всей библиотеке Google больше не
  предоставляет.
